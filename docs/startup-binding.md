# Initialized startup binding

`scripts/startup_binding.py` only reads and locks an independently initialized installation. It is not connected to the installer, startup shell, quota service or systemd. Missing, legacy, conflicting, partial, pending or unknown evidence is retained and rejected; the reader never initializes, adopts, repairs, admits, closes, reopens or grants readiness.

The public `Gate.inspect_initialized()` context acquires exclusive activity before coordinator. An existing shared activity owner can still take coordinator to confirm its own result while inspection waits. The context then requires the exact installation UUID, protected initialized directories and lock identities, OPEN state and completed operation/fence history. It yields copied evidence without operation authority. The public allocation context takes allocation last, verifies its UUID, pointer, projects and the complete bounded commit chain, and rejects pending projects. Both contexts compare records and identities before releasing their owned locks. The startup reader shares one finite lock-acquisition deadline, with allocation capped at ten seconds. Count-bounded journal reads, filesystem IO and OS creation do not have a wall-clock guarantee.

Protected host intent, final record, exact durable storage receipt and configuration must name the same canonical installation UUID and geometry. The receipt's recorded LUKS UUID must match the backing file, the active LUKS2 mapper must use that exact loop backing file, and the exact mount target must be encrypted XFS with writable project quota enforcement and `nosuid,nodev`. Native queries use the existing supervised command boundary and fixed absolute programs/arguments. Python never reads backing or unlock-key bytes; the fixed cryptsetup UUID query inspects the LUKS header. Current ancestor/control directories and host/config/backing/key files remain held through read-only descriptor checks. No secrets or configuration values are returned; the closed result contains evidence digests and the installation UUID.

The existing `runtime_layout.verify()` remains unchanged. It permits populated permanent storage and an independently validated new build tmpfs identity after reboot, preserving its owner/mode/capacity/nosuid/nodev semantics. Permanent directory identities remain exact. No saved receipts are rewritten.

Success is only `STARTUP_BINDING_ONLY`, `changed:false`, `backupReady:false`. It describes the held invocation and cannot authorize subsequent work after its locks release. It does not verify every project's native quota limit, databases, external effects or all-platform backup consistency. Valid terminal assertions whose uncertainty-marker creation also failed retain the existing admission primitive's evidence limitation; this reader does not invent uncertainty or completion. Linux ownership, flock, mapping/XFS behavior, crashes, durability and installed service behavior need separate native qualification. Local controls run isolated Python with bytecode disabled (`-I -B`), inject Linux path presentation, DAC, directory/file FD and mount transports, and exercise actual retained record IO and replacement behavior. Future entry-point wiring must preserve that interpreter policy; ambient import caches are outside these controls. There is no initialized-VM adoption or startup activation in this slice.
