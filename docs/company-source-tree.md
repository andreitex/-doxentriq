# Protected company source retention

The source-tree checkpoint (private installation record; not distributed) records 33 passing injected controls without skips. Independent review and root readback verified 35 stable source/evidence inputs and the complete five/five-fragment draft changes. This API creates retained company source bytes; native installation remains disabled.

`authenticated_source_request` derives an action before any current-stage intent or filesystem effect. It requires a genuine live verifier-issued source, an explicit shared installation-request hash and the exact fresh encrypted-storage context. Signed source rows, counts, limits and logical Git tree are independently checked. The action also covers captured materializer bytes and the preceding artifact-store request, action, module and canonical closed outcome.

`materialize_authenticated_company_source` requires the actual held installer parent for `company-source-materialize`. Its preceding Store intent and independent confirmation must match the same installation request and the independently reconstructed outcome. All twelve original artifacts and journals are held and remeasured before creating a source directory. A journal boolean alone grants no authority.

The parent `company/source-releases` must be independently precreated, root-owned, mode `0700` and empty. An exclusive release-SHA child is created, then its intent is synced and read back before source payload is written. The exact signed nested inventory is retained under `source`; every file becomes `0400` and every source/release directory becomes `0500`. Signed `100644`/`100755` modes remain logical Git metadata. Full nine-field path/descriptor identities, bounded byte readback, exact inventories and narrowly checked owned creation/mode transitions protect the result. Partials, orphans and uncertain closes are preserved and cannot be adopted or automatically retried.

Limits are 2,048 files, 512 source directories, 8 MiB per source file, 64 MiB total source bytes and two journal records of at most 64 KiB each. These are finite source policies, not native disk, descriptor or performance reservations. The injected backend explicitly adds offset reads; the older SeedFiles and StoreFiles interfaces and limits remain unchanged. Success requires known closure of every owned handle; acknowledgement additionally requires the caller to close the outer source, parent and storage contexts.

The stored-source verifier checkpoint (private installation record; not distributed) separately records 16 new controls, 32 schema4 controls and 23 issuance controls, all without skips. Its explicit `authenticated_stored_platform_source` factory authenticates the captured signature and independent public-key fingerprint before parsing or executing the captured parser. It requires stored root-owned files at `0400`, relevant directories at `0500` and exact matching release-SHA paths. The external key retains the original full-nine protection policy and may have a `0700` parent. The original producer factory still requires its existing physical `0644`/`0755` policy.

That verifier authenticates signed artifacts and their exact parser. A complete physical execution-tree guard, independently selected confirmed installation stages, captured operational-module loader, native resource qualification and reboot caller are separate requirements. Neither checkpoint establishes those requirements, company signing, full installation or production acceptance. Earlier fixture failures, inert reader corrections and retained raw runs remain historical evidence.
