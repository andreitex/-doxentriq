# Protected application metadata

Application names and descriptions are rejected before persistence when the existing redactor detects credential syntax or an exact known configured platform value. Enter credentials through protected connection forms. Ordinary metadata is preserved.

The shared control helper derives provider keys, broker/report/metrics tokens, the OIDC client secret, the platform encryption key in base64, and encoded/decoded password components of configured URLs. Public client IDs, endpoint hostnames and URL usernames are not added as secrets. It retains the existing four-character minimum and literal matching, including JSON-escaped spellings. It does not read endpoints, decrypt application credentials or export the configuration.

Configured dependencies pass that list to official research redaction and the actual model gateway. Every gateway prompt and system message is redacted immediately before reservation and request assembly, including serialized metadata in legacy queued applications. Actual provider credential headers are preserved. Legacy database records are not rewritten and no full configuration, secret list or provider prompt is added to billing records.

Local regressions use synthetic values and injected model responses; no provider or research network request is made. This protects known values and existing recognized credential syntax. It does not establish detection of unknown opaque credentials, vault-secret redaction, live provider behavior or deployment qualification.
