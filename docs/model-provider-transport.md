# Model provider transport

The gateway uses the fixed OpenAI Responses and Anthropic Messages HTTPS endpoints. Credential-bearing requests reject redirects; a substituted response URL is unavailable even when it has the same origin. Requests retain their existing five-minute deadline. No private provider response, transport exception or parsing exception enters the workflow error.

Successful receipts require HTTP 200, an object JSON response, valid UTF-8 and at most 8 MiB of streamed decoded bytes. Content-Length must be bounded and well formed; uncompressed lengths must match the actual bytes. Compressed response lengths describe wire bytes, so the decoded stream has its own independent limit. Client refusal bodies are cancelled without being read.

Only the fixed client-refusal statuses 400, 401, 403, 404, 422 and 429 can release that call's reservation at zero and use the existing bounded fallback. Other statuses, redirects, malformed or interrupted receipts and unavailable cancellation retain the reservation and stop dispatch. This is a gateway policy; real provider billing and account behavior still require qualification. Reconciliation never assumes a held call was free.

An interrupted running or uncertain call blocks another provider dispatch for its workflow. Recovery records a durable attention state instead of automatically requeuing model work. Stale deliveries, explicit resume and additional spending cannot bypass the unresolved call record. The UI shows company reconciliation guidance without retry controls. Reservations remain held even if a crash occurred before their IDs were linked into the call record; settlement alone does not resolve an uncertain call. No provider reconciliation endpoint or idempotency guarantee is implemented.

Production wiring records a bounded encrypted output checkpoint together with completed call metadata in one Store transaction. Replay binds the job, explicit attempt, application baseline, logical specification/implementation/review slot and exact request hash, with current caller lease ownership and app/job fences checked before any cache hit or spending. Implementation repairs and final review remain distinct logical slots even when both use strong review routing. Replayed outputs create no new call, reservation, settlement, billing event or charge. A missing, changed or unauthenticated checkpoint pauses instead of paying to regenerate it.

AES-256-GCM private checkpoints and frozen generation contexts use the installation secret key and authenticated identity/metadata bindings; serialized output is limited to 8 MiB and context to 12 MiB. The billing API returns only its separate output-free call records. Context freezes the original source and specification for the attempt, while model prompts exclude app status, URLs, timestamps and worker fences. Recovery rechecks current business inputs, schema, request/answer/repair feedback, baseline, connection scope and research freshness, then uses the current caller fence with the original model-visible input. Restart or an approved budget increase keeps the attempt; explicit resume and automated repairs create a new attempt. Generated output never authorizes publication or an external action.

If persistence fails before the output transaction commits, the paid call remains uncertain even after a known settlement. Unknown provider outcomes retain their existing hold. A lost commit acknowledgement cannot overwrite an already completed checkpoint in the catch path. Older completed call metadata without retained outputs requires company reconciliation. No provider idempotency or automatic billing reconciliation is claimed. Local injected checks and JsonStore reopening do not establish live provider reconciliation, power-loss durability or native MySQL crash durability.

Required input/output usage must be actual nonnegative safe integers. Optional absent or null cache counters remain zero; strings, booleans, fractions and inconsistent counts are unavailable. OpenAI cached and cache-written counts cannot exceed its total input; Claude input accounting adds ordinary, cached and cache-written inputs. Observed input must fit the reserved conservative input bound, and output must fit the reserved output limit. The reservation uses the largest configured ordinary, cached or cache-write input rate. A validated billed partial completion settles once, then fails without retry.

The [OpenAI cache accounting documentation](https://developers.openai.com/api/docs/guides/prompt-caching) describes its three input categories. The existing company model catalog and provider request schemas remain separately managed. This change adds no model IDs, prices, API calls or new qualifications.

Local tests inject synthetic responses into the actual gateway and cover credential routing, spending holds, bounded fallback, malformed billing, streaming limits, cancellation and compressed-length interpretation. They do not establish live provider behavior, production image qualification or real model quality.
