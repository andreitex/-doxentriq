# Trusted quota command supervision

`quota_runtime.output()` serializes command admission through one module-owned lock. Lock waiting counts toward the existing command deadline (at most ten seconds); captured ASCII output remains limited to 32 KiB. The original argument list, private environment, new session, closed descriptors, and private stderr behavior are unchanged.

The actual quota helper uses `ThreadingMixIn` with up to four request workers and read-deadline timers. Its company-managed helper, allocation, and checkpoint sources have no foreign `waitpid` calls or SIGCHLD reapers. Every command launch passes through `output()`. POSIX admission requires the default SIGCHLD disposition and pidfd/P_PIDFD support. This is a trusted sole-reaper contract, not protection against hostile code or descriptor manipulation inside the privileged helper. An unrelated reaper cannot be proven absent dynamically; adding one requires changing this contract before use.

The child remains unreaped from creation through pidfd acquisition under that contract. `WNOWAIT` observations validate the direct child through its private pidfd; successful POSIX execution never uses `Popen.poll()` or numeric `Popen.wait()`. Failed pidfd creation permits only WNOWAIT cleanup of the still-owned direct child, never successful execution.

Before reaping on both success and failure, cleanup terminates the still-owned process group. After reaping, only signal-zero observations are allowed. Confirmation requires group absence; a present, inaccessible, or possibly reused group cannot receive a termination signal and prevents confirmation. Descendants deliberately escaping the command's new session are outside this trusted-tool process-group contract. Termination does not reverse quota or filesystem effects already performed.

Cleanup uses one additional five-second deadline for reap, group absence, and reader completion. Kernel process creation, uninterruptible system calls, and Python scheduling do not have universal wall-clock guarantees. An uncertain reap, pipe, descriptor, lock release, or group observation returns the fixed private error and latches later command admission closed. Retained process/reader references avoid destructor-driven numeric reaping. No uncertain operation is automatically replayed; the existing pending allocation journal and checkpoint boundaries remain authoritative and unchanged.

The new controls inject POSIX pidfd/waitid/group behavior and include actual local threads for parallel admission. The existing helper suite also runs bounded Windows Python commands. These controls do not qualify native Linux pidfd/group semantics, XFS behavior, power loss, the installed helper, or production deployment. Company Linux qualification remains required. No Gate, Allocation, helper service, startup, bootstrap, or installer source changes are part of this slice.
