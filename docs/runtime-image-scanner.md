# Runtime image scanner

The trusted broker's image scanner has a separate bounded executor and an encrypted active-job record. Publication remains unavailable until the scan, its coverage evidence, and independently confirmed cleanup all succeed. This source has local verification; native scanner and Linux crash acceptance remain pending.

Before any daemon command, the broker retains synchronized encrypted intent and claims an atomic coordinator directory. Other broker processes cannot claim it concurrently. An active, unreadable, malformed or uncertain record blocks a new scan after restart. The broker does not delete an old lock based on age or discover containers by name. Company inspection is required when an operation cannot prove cleanup.

The scanner selects the fixed local Docker socket with a fresh empty protected configuration. Its stdout and stderr are separate, bounded channels; overflow, nonzero exit, cancellation or an unreaped child make the scan unavailable. Raw bounded results are retained encrypted before IDs or reports are interpreted. Registry credentials remain private inputs on encrypted storage and never enter public findings.

One digest-pinned scanner container uses gVisor, UID10001, a read-only root, dropped capabilities, one CPU, 1 GiB memory, 128 processes and 128 MiB temporary storage. Its only binds are the read-only scanner cache and company CA. The artifact network and registry address are independently resolved through the trusted daemon. Before start, the broker checks the full immutable container ID, selected image descriptor, complete configuration, mounts, resource limits, environment and sole network identity; the actual profile is retained and compared throughout cleanup. Cancellation after creation can authorize detached ownership inspection and cleanup, but never a start.

Cleanup can stop and remove only the original container whose full profile still matches. A complete independent container inventory must then prove absence. The durable final state precedes the clear marker and removal of the same empty coordinator directory. Crashes, profile drift, unknown create output and unconfirmed absence preserve the blocker and evidence. Journals and private input files are retained.

The cache has an explicit runtime-to-host mapping. Ordinary single-link metadata and database files are size-bounded and fully hashed before and after execution. The metadata must use schema2 and be no more than 24 hours old. A publisher's earlier `NextUpdate` schedule does not silently reduce that policy. This does not waive the 24-hour limit or permit a changed feed during scanning.

Reports must name the exact requested immutable image, use the expected container-image schema and include positive package evidence for a supported Alpine or Debian OS result. Malformed reports and unsupported coverage remain unavailable. This positive OS-package requirement does not establish completeness of every language or dependency analyzer. The fixed trusted Docker29/containerd inspection boundary also does not independently hash raw parent/config OCI content.
