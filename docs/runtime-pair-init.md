# Fresh runtime pair initialization

`runtime_pair_init.initialize` is an explicit fresh-only company stage. Its
default entry refuses execution: no native installer-parent authority adapter is
implemented. Copied session IDs and arbitrary callables do not grant authority.
Only explicit trusted test adapters are supported by this source slice; every
record/result keeps native authorization false. This is not protection against
hostile privileged code inside the trusted initializer.

The read-only `fresh_storage_context` binds the original host intent/final and
retired pending storage receipt to the configuration UUID, backing LUKS UUID,
active mapper, encrypted XFS target and saved/current runtime layout. It holds
finite noninheritable directory/record descriptors through the invocation and
checks them again. Backing/key bytes are never read by Python; the fixed native
LUKS UUID query would read the header. Native commands, mounts, permissions,
flock, crash durability and installer authorization remain unqualified locally.

Before effects the quota inventory, both journal paths and projects must be
wholly absent, storage empty and prior pair-stage evidence absent. An existing
empty projects file is rejected. The protected stage lives under `config`, not
the quota namespace. Its exclusive fsynced/read-back intent precedes Gate mkdir
and lock creation. Gate initializes first, then its exclusive inspection ends
before the existing allocator initializer obtains an admitted shared activity
lease. The allocator's existing uncertainty journal is preserved.

The new stage holds its own directory and every immutable stage record through
completion, checks exact progressive inventory and canonical values, and closes
only its own descriptors. Equal-looking boolean/float fields cannot pass as
integer proposal fields. Unknown leaves, replaced directories/records or changed
earlier confirmation evidence block later effects and terminal confirmation.

Completion independently reads the exact fixed empty projects bytes/hash,
sequence-zero allocator records, and the single confirmed initialization
operation, then calls the initialized read-only startup verifier. No learned
state/hash, adoption, reset, replay, cleanup or pending fallback exists. Every
partial effect, unknown result, lost acknowledgement and even prior completed
stage blocks another fresh call. A final effect-observation record is not a
portable authorization token: later guard/adapter failures can still prevent a
successful return. Existing state requires separate company reconciliation.

Parent evidence uses the exact Bash session format `s-[A-Za-z0-9]{12}`:
the prefix and twelve ASCII letters or digits are required, with an exact
string type and no extra whitespace. The installation identity remains a
separate canonical UUID. Session syntax does not establish held-parent
authority; the trusted adapter still checks the exact active evidence.
Earlier UUID-based injected stage hashes and all partial or completed stage
records are retained unchanged and block fresh entry. There is no format
conversion, dual-format fallback, migration, adoption or replay.

Future installer wiring must keep the original parent lock, close its FDs in
children, render before this stage, and finish the stage before starting the
quota service/brokers/apps. Foundation-only setup must not initialize the pair.
Initialized startup uses `layout.verify`, never fresh `layout.prepare`; service
startup needs its own read-only initialized check before socket/effect admission.
None of this wiring or service behavior is implemented here.

The scope is `FRESH_RUNTIME_PAIR_ONLY`, with `backupReady=false`. No automatic
resume, whole-platform backup readiness, post-lock future authority or installed
VM acceptance is inferred. Finite lock deadlines do not bound all filesystem IO
or imply cancellation of uncertain effects. Local controls inject root/DAC,
Linux directory/file-FD behavior, mounts/commands and parent authority, while
retaining actual bounded file IO and partial evidence.
