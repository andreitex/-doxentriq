# Document management reference

This company-maintained reference application and golden request fixture is not evidence that a model generated or deployed it successfully. The React browser offers app-scoped SSO/local-account sign-in, folders, uploads, metadata search, downloads, version restore, archive, audit, and approved read-only Samba access. Backend permissions remain authoritative.

The runtime starts `node /app/server.mjs` on port 8080. The platform acquires dependencies using `npm ci --ignore-scripts`; custom `npm run build` and `npm test` commands build the React assets and exercise document preservation, transaction rollback, permission denials, JWT identity, MCP scopes, connector paths, quota, and integrity. Node 24 is the runtime target. `manifest.json` and `pipeline.json` are reference inputs; substitute the authorized app ID/slug and requested approved connection IDs before materializing a release. Dependencies/security/image/preview/migration stages have empty custom commands and are performed by trusted platform services. Custom acceptance commands run offline against read-only build output. The application cannot issue its own deployment evidence.

The company migration service applies `migrations/001_documents.sql`; the runtime never performs DDL. Include this additive migration in the generated release migration list. MySQL uses InnoDB, app-scoped rows, TLS with certificate validation, bound parameters, unique version numbers, row locks, and transactional audit records. Storage uses immutable random blob IDs and SHA-256 integrity checks under the encrypted quota mount provisioned by the platform. Restore appends a version pointing to preserved content. Archive hides a document from normal search and retains content, versions, and audit. A failed database transaction after a blob write preserves that recoverable orphan; later cleanup requires a reviewed recovery policy.

Required settings: `APP_ID`, exact HTTPS `APP_ORIGIN`, `APP_TLS_CERT_FILE`, `APP_TLS_KEY_FILE`, `APP_STORAGE_ROOT`, `APP_STORAGE_QUOTA_BYTES`, `MYSQL_HOST`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD_FILE`, `MYSQL_CA_FILE`, `OIDC_ISSUER`, `OIDC_AUDIENCE`, `OIDC_JWKS_FILE`, `OIDC_JWKS_RESOURCE_ID`. `MYSQL_PORT` defaults to 3306. Production serves HTTPS on port 8080 with app-scoped certificate/key files and a TLS 1.2 minimum; absent or partial pairs fail closed. Only explicit `NODE_ENV=test` or `local` allows a local HTTP transport. Secrets/local JWKS come from the app's read-only `/run/app-secrets` mount. No global platform credential, plaintext database connection, production in-memory fallback, or remote JWKS fetch is used. The platform must provide encrypted storage/database volumes and trusted quota enforcement; this app does not attest encryption from a path.

The company broker immediately refreshes issuer-bound signing keys and repeats every five minutes. The scoped `jwks.json` contains public keys plus an `autosoft` receipt binding exact app/resource/issuer, public-key hash and a maximum one-hour validity. This app reads and validates that atomic file on every authenticated request and updates its verifier when keys change, so a cached verifier cannot bypass stale evidence. Missing, changed, expired or foreign receipts return sign-in unavailable. `OIDC_JWKS_RESOURCE_ID` is the exact published app ID, or app ID plus `_preview` for its isolated preview. Generic apps that cache keys are reloaded only after exact owned-container/image/route verification. If refresh remains unavailable beyond one hour, the broker records and stops only the exact managed app; only that recorded stop may resume after fresh owned keys and health verification. Manually stopped apps stay stopped. Keycloak recovery codes are not implemented or claimed by this reference app.

The Keycloak public app client permits code PKCE S256, exact app redirect URI and web origin, and no implicit/password flow. JWTs require issuer/signature/expiry, exact API audience and mandatory `app_id`. Permissions come only from `resource_access[OIDC_AUDIENCE].roles`: `dms.read`, `dms.search`, `dms.write`, `dms.admin`. App `dms.admin` grants document permissions, archive and audit. Realm/platform-owner roles grant nothing. Assign staff groups only required roles. Browser state/verifier live temporarily in sessionStorage; access tokens remain in memory and disappear on reload or sign-out. APIs accept no cookies or identity headers.

`POST /mcp` is a stateless Streamable HTTP endpoint with JSON responses; GET returns 405 because there is no server-initiated SSE stream. Supported versions: 2025-03-26, 2025-06-18, 2025-11-25. Requests need exact `APP_ID:mcp` audience and matching `app_id`. `search_documents` also requires app-client `dms.search` and scope `dms.search`; `get_document_versions` requires app-client `dms.read` and scope `dms.read`. Configure MCP tokens to include the app client's roles; scope alone grants nothing. Browser API tokens cannot call MCP. Origin is validated when supplied; Accept must include application/json and text/event-stream. Document/connector content remains untrusted. Transport reference: https://modelcontextprotocol.io/specification/2025-11-25/basic/transports

Optional Samba needs both app-scoped `CONNECTOR_REGISTRY_FILE` and `CONNECTOR_TOKEN_FILE`. An adapter is not assumed available. The registry has `schemaVersion:1`, `connections` with `id`, `type:"samba"`, `reviewStatus:"approved"`, `appIds`, one logical `roots` entry, `capabilities` (`files.list`, `files.read`), trusted HTTPS `adapterUrl`. The adapter must independently validate token/grant/root. The app POSTs to `<adapterUrl>/v1/connections/<id>/list|read` with `{appId,root,path}` and its dedicated bearer token. Listings return `{entries:[{name,kind:"file"|"directory"}]}`; reads return `{contentBase64,mime}`. Redirects, traversal, writes, unapproved apps and oversized responses are refused. No SMB credentials or share/host mounts enter the application. Company connector registration/delivery is required before enabling this feature.

Retention deletion, OCR, malware-content classification, workflow approvals, per-document ACLs, full-text content indexing, and legal retention are further business requirements. A passing source suite does not replace live TLS MySQL, Keycloak, encrypted storage, connector, browser, or deployment testing.

Use the administration Access view to define app roles from the declared `dms.read`, `dms.search`, `dms.write` and `dms.admin` permissions, review the exact policy change and issue a separately approved local-account invitation. The broker enforces those leaf permissions through app-specific composite roles and requires TOTP enrollment. Retired roles lose their leaf permissions; code rollback does not restore access policy. Microsoft/Google mappings retain immutable provider tenant/group IDs but remain pending validation until an authorized directory resolver is implemented and tested. An ordinary SSO login does not activate group authorization. Company operators can independently inspect actual effective Keycloak assignments through their protected CLI; Keycloak-local group UUIDs and upstream provider group IDs are different identifiers. No identity credentials belong in the app or chat.

`chat-update.json` and `tools/dms-reference.test.ts` provide a deterministic update fixture. It invokes the real generation service with injected responses, checks full omitted-source/lock/migration preservation, builds the merged React UI, and exercises project-code metadata search and preserved bytes using test-only repositories. It also rejects mismatched app identity, protected infrastructure and rewriting recorded migrations. No live model, API key, qualification, production job, security receipt or deployment result is created. Exclude this README, golden/update fixtures, reference manifest/pipeline files and `scripts/refresh-lock.mjs` from materialized runtime source. The maintenance helper only extracts the independent lock from the company's resolved platform lock; it is not an application runtime command.
