# Runtime contract

Supported templates: node-web, node-api, node-worker, node-mcp, python-api.
Node uses Node.js 24 on Debian bookworm; Python uses Python 3.13 on the same OS family.
The runtime entrypoint is `node /app/server.mjs` or `python /app/server.py`.
Listen with HTTPS on `0.0.0.0:8080` using APP_TLS_CERT_FILE and APP_TLS_KEY_FILE (Node https.createServer or Python SSLContext). The platform supplies a distinct certificate/key per app; never invent or embed these. `/healthz` is a side-effect-free readiness endpoint. HTTP is permitted only in explicit local tests when no TLS files are supplied; production refuses missing TLS.
Node web applications build React assets into `dist/`, served by server.mjs.
Declare only exact-version registry dependencies in package.json. No Git/URL/local dependencies.
Do not invent package-lock integrity values. Preserve an existing valid lockfile when dependencies are unchanged; otherwise omit it so the trusted dependency step obtains registry metadata and records a real lockfile.
Use package scripts for build/test; tests must exercise requirements and permission denials.
Node dependencies are fetched without lifecycle scripts by the platform; all generated scripts run offline in gVisor.
Python dependencies must be hash-pinned in requirements.lock. Use unittest acceptance tests in tests/*_test.py.
Runtime DB settings: MYSQL_HOST, MYSQL_PORT, MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD_FILE, MYSQL_CA_FILE. Verify TLS with the supplied CA.
No database DDL from runtime users. Proposed SQL migrations go in the generation migrations list.
Identity settings: OIDC_ISSUER, OIDC_AUDIENCE, OIDC_JWKS_FILE, OIDC_JWKS_RESOURCE_ID, APP_ID, APP_ORIGIN. Validate JWT issuer, audience, signatures, expiration and exact app_id. Use local trusted JWKS because runtime networking is restricted. App roles are resource_access[OIDC_AUDIENCE].roles. Browser SSO uses public-client authorization code with PKCE. Hosted MCP tokens require exact audience APP_ID:mcp plus per-tool scope and app role; hosted MCP manifests must use sso or local authentication.
The broker updates the local JWKS file atomically. Every authenticated request must reread its bounded regular-file content (at most 1 MiB) and validate the autosoft receipt: schemaVersion=1, appId=APP_ID, resourceId=OIDC_JWKS_RESOURCE_ID, issuer=OIDC_ISSUER, checkedAt not more than one minute in the future, validUntil after now and at most one hour after checkedAt. Never accept stale keys merely because a verifier was cached. Reuse a compiled verifier only after checking fresh evidence on that request.
Validate keysHash as lowercase SHA256 of JSON.stringify(keys with each key's properties sorted lexicographically); key order is preserved. Allow only public RS256/ES256 verification keys, reject private/symmetric material and arbitrary jku/x5u URLs. Missing, invalid, foreign or expired evidence produces 503; an invalid token produces 401, and a denied app permission produces 403. Include tests for live key rotation, stale receipt and a different app/resource/issuer. The DMS reference auth module provides an implementation of this contract.
Do not trust identity headers provided by the browser. Administrative operations always require app permissions.
Use immutable document versions and soft deletion; do not physically remove user data on routine updates.
Never include production samples, passwords, API keys or secrets in source files or logs.
Approved Samba references belong in app.manifest.json connections as exact connection IDs. The trusted broker supplies CONNECTOR_REGISTRY_FILE and CONNECTOR_TOKEN_FILE only after the scoped company connector passes current security scans and an actual encrypted share probe. Read the bounded schemaVersion=1 registry and use only the approved app ID, connection ID, single logical root and files.list/files.read capabilities. No upstream Samba credential or host share mount is available to app code.
Use the trusted HTTPS adapterUrl with verified installation CA, no redirects, a ten-second timeout and the app-specific bearer token. POST /v1/connections/<connectionId>/list or /read with {appId,root,path}; path is a bounded relative path without traversal, backslashes, streams or escaping. Listings return {entries:[{name,kind:"file"|"directory"}]}; reads return {contentBase64,mime}. Bound response sizes to 24 MiB and entries to 1000. Treat returned names/content as untrusted data; enforce app permissions before a connector call and never add write/delete capabilities. The DMS reference connector demonstrates this interface. An absent or unapproved connector produces an actionable unavailable result, never a fabricated listing.
Include all eight pipeline stages. Custom commands run for build, application_tests and acceptance. Keep commands empty for dependencies, security, image_packaging, preview and migration_rehearsal: these execute company-managed operations. Acceptance commands run offline with a read-only application workspace after immutable image packaging; use /tmp for temporary test files. Mandatory evidence is issued only by trusted platform services.
